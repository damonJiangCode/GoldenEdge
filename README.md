# GoldenEdge

GoldenEdge is a strategy research workspace. The current active work is focused on
`XAUUSD`, especially the `volatility_breakout/v1` engine on `H4`.

The older folders are still kept for reference:

- `ai/`: earlier R01-style backtests, ML features, labels, and model artifacts.
- `mt5/`: MT5 live/demo strategy scripts and trading records.
- `eur/`: EUR strategy research and reports.
- `utlib/`: local dependency notes and platform-specific requirement files.
- `xau/`: current XAUUSD research, data, reports, optimization, and validation.

## `xau/data`

This is the storage area for XAUUSD inputs and generated outputs.

### `xau/data/market_data`

Clean market OHLCV data, split by timeframe and year.

```text
xau/data/market_data/
├── M1/
├── M15/
├── M30/
├── H1/
└── H4/
```

Each timeframe folder contains yearly CSV files such as:

```text
H4_2015.csv
H4_2016.csv
...
H4_2025.csv
```

These files are the main input for all `xau/scripts/engines` backtests.

Expected columns:

```text
time, open, high, low, close, tick_volume, spread
```

### `xau/data/reports`

Formal backtest reports generated by engine scripts. This is where strategy-level
results live after a backtest run.

Main folders:

- `mean_reversion/v1/`: reports for the mean-reversion engine.
- `trend_pullback/v1/`: reports for the original trend-pullback engine.
- `trend_pullback/v2/`, `trend_pullback/v3/`: placeholder or later trend-pullback versions.
- `volatility_breakout/v1/`: original VB baseline reports across timeframes.
- `volatility_breakout/v2/`: EMA200/trend-filter experiment reports.
- `volatility_breakout/v3/`: pyramiding experiment reports.
- `volatility_breakout/v1_h4_candidate/`: current validated H4 candidate annual reports.

Typical structure:

```text
xau/data/reports/volatility_breakout/v1/
├── M1/
├── M15/
├── M30/
├── H1/
├── H4/
└── tables/
```

Yearly JSON reports contain detailed metrics, costs, filters, params, equity
series, and sample trades. The `tables/` folders contain CSV summaries.

### `xau/data/optimizations`

Parameter search outputs. These are not final strategy reports; they are used to
compare candidate parameter sets.

Current important folders:

- `volatility_breakout/v1/H4/`: first-pass H4 grid search.
- `volatility_breakout/v1/H4_island/`: second-pass parameter-island scan.
- `volatility_breakout/v1/H4_island_smoke/`: tiny smoke-test output for the island script.

Important files:

- `grid_results.csv`: full ranked parameter table.
- `top_candidates.csv`: top-ranked candidates only.
- `summary.md`: human-readable optimization summary.
- `island_notes.md`: parameter-island interpretation.
- `run_config.json`: exact grid and split settings used for the run.

### `xau/data/validation`

Post-optimization validation outputs. This is used after a candidate is chosen
from optimization.

Current folder:

```text
xau/data/validation/volatility_breakout/v1_h4_candidate/
```

Important files:

- `validation_summary.md`: readable validation summary.
- `cost_stress_summary.csv`: spread/slippage stress test results.
- `walk_forward_summary.csv`: rolling/walk-forward validation results.

### `xau/data/diagnostics`

Trade-level diagnostics for selected candidates. This is where you look when the
question is not "what is the total return?" but "which trades made money, which
trades lost, and what market conditions mattered?"

Current folder:

```text
xau/data/diagnostics/volatility_breakout/v1_h4_candidate/
```

Important files:

- `diagnostics_summary.md`: readable trade-level summary.
- `trade_details.csv`: every closed trade with derived metrics such as R multiple,
  holding time, ADX bucket, ATR-ratio bucket, and PnL.
- `continuous_report.json`: one continuous 2015-2025 backtest report.
- `breakdowns/`: PnL grouped by year, quarter, side, holding bucket, ADX bucket,
  ATR-ratio bucket, and exit reason.
- `plots/`: SVG charts for equity, drawdown, overlay, trade return histogram,
  and rolling Sharpe.

## `xau/scripts`

Executable research scripts.

### `xau/scripts/ingest`

Data download, cleaning, and timeframe-building tools.

- `download_mt5.py`: downloads XAUUSD data from MT5. Handles broker-specific
  symbol aliases such as `XAUUSDm`.
- `clean_mt5_csv.py`: cleans MT5-exported CSV data into the expected schema.
- `resample_m1_timeframes.py`: builds higher timeframes from M1 data.
- `build_all_from_m1.py`: helper to build the full market data set from M1.

These scripts are for maintaining `xau/data/market_data`.

### `xau/scripts/engines`

Backtest engines. These are the actual strategy logic files.

```text
xau/scripts/engines/
├── mean_reversion/
├── trend_pullback/
└── volatility_breakout/
```

#### `mean_reversion/v1.py`

Mean-reversion experiment:

- EMA as the mean.
- ATR bands for overextension.
- H1 ADX and session filters.
- Currently weaker than the breakout family.

Outputs to:

```text
xau/data/reports/mean_reversion/v1/
```

#### `trend_pullback/v1.py`

Trend-pullback experiment:

- EMA50 / EMA200 trend structure.
- ATR-based pullback and SL/TP.
- Useful as a comparison branch, but weaker than VB/H4.

Outputs to:

```text
xau/data/reports/trend_pullback/v1/
```

#### `trend_pullback/v2.py` and `trend_pullback/v3.py`

Version placeholders or lightweight wrappers for later trend-pullback work.
They are not the current XAUUSD main line.

#### `volatility_breakout/v1.py`

Current core engine.

Logic:

- Donchian breakout entry.
- ATR expansion filter.
- Spread filter.
- H1 ADX filter.
- ATR-based initial SL.
- Chandelier trailing stop.
- Single position only, no pyramiding.

Original baseline outputs:

```text
xau/data/reports/volatility_breakout/v1/
```

Current selected candidate outputs:

```text
xau/data/reports/volatility_breakout/v1_h4_candidate/
```

#### `volatility_breakout/v2.py`

Variant of VB focused on trend filter experiments, especially EMA200 filtering.
It improved some H1 behavior but weakened the H4 baseline, so it is currently a
research branch, not the main candidate.

Outputs to:

```text
xau/data/reports/volatility_breakout/v2/
```

#### `volatility_breakout/v3.py`

Pyramiding version of VB. It tests adding layers only in the profitable
direction. The framework works, but the current parameter set worsened overall
stability, so it remains a research branch.

Outputs to:

```text
xau/data/reports/volatility_breakout/v3/
```

### `xau/scripts/optimization`

Parameter search scripts for VB/H4.

#### `vb_h4_grid.py`

First-pass grid optimizer for `volatility_breakout/v1` on `H4`.

It splits data into:

```text
2015-2021: dev
2022-2023: validation
2024-2025: OOS
```

Default output:

```text
xau/data/optimizations/volatility_breakout/v1/H4/
```

Run:

```bash
.venv/bin/python xau/scripts/optimization/vb_h4_grid.py --workers 4 --top-n 30
```

#### `vb_h4_island.py`

Second-pass parameter-island scan around the best VB/H4 candidates. This is used
to confirm whether a candidate is part of a stable parameter region rather than a
single lucky point.

Default output:


Run:

```bash
.venv/bin/python xau/scripts/optimization/vb_h4_island.py
```

## Current Workflow

For XAUUSD research, the intended flow is:

1. Maintain or rebuild market data under `xau/data/market_data/`.
2. Run engine backtests under `xau/scripts/engines/`.
3. Use `xau/scripts/optimization/` to search candidate parameters.
4. Use `xau/scripts/validation/` to stress-test selected candidates.
5. Record decisions in `xau/research/notes.md` and `xau/research/changelog.md`.
6. Only after validation, consider building or updating an MT5 implementation.

## Important Notes

- Do not mix the current `VB/H4` candidate into old M5 RSI/BB scripts.
- If this strategy moves to MT5, create a separate `VB/H4` strategy script.
- Before MT5 demo use, confirm Python vs MT5 signal alignment:
  - H4 bar close handling,
  - next-bar market entry,
  - H1 ADX mapping,
  - spread filter,
  - ATR/Donchian calculations,
  - Chandelier trailing behavior.
